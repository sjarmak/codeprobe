# R0 file-read campaign, K=3 — 2026-07-29

This campaign repeated the five-repository R0 comprehension experiment after
making source-file reads an explicit task requirement. It first ran a fresh
seed-1 gate and expanded to three seeds only after every repository exceeded
the preregistered `0.80` identical-pair-yield floor.

`MeasurementObservationV1` observations (70 tasks × two admission arms ×
three seeds). Every repository is `NativeComposed`, high-confidence,
calibrated, eligible, and above the gate. Convention inputs are not degraded.

The full campaign executed 630 canonical codeprobe trials: 70 tasks × three
configurations × three seeds. The configurations were:

- `baseline`: `claude-sonnet-4-6`
- `harness_swap`: `claude-haiku-4-5`
- `aoa_migrated`: `claude-sonnet-4-6`

All configurations disallowed `Bash`. Every admission-relevant
`harness_swap` and `aoa_migrated` task/seed trace contains an actual `Read`
event. One non-admission Isort baseline trial in seed 3 used only `Grep`; it is
retained as an honest protocol-compliance exception and did not enter the
paired AOA evidence.

## Findings and disposition

The campaign exposed five codeprobe-owned or codeprobe-adjacent findings:

1. `codeprobe-xqpm`: the declared 600-second timeout was previously not
   enforced when the project CLI resolved stale code. Fixed and closed in
   `b39b601`/`e5a7367`. This campaign then observed exact typed timeouts near
   600 seconds on the Gunicorn import-chain task, while the run continued.
2. `codeprobe-v3wn`: the project-root virtual environment could silently bind
   to a stale worktree. Fixed and closed in `74bdb63` with a provenance guard,
   regression coverage, and repair guidance.
3. `codeprobe-o8pw`: uncontained agents could leak root `answer.json` files
   into pinned source checkouts. Fixed and closed in `1e9e51b`. Seed-2 and
   seed-3 leaked files from this pre-fix campaign were preserved in
   `operator-artifacts/`; all ten pinned checkouts were restored byte-clean.
4. `codeprobe-ymxn`: a preserved Rich retry attempt reported Claude's
   “session limit” response as a generic agent failure. The codeprobe agent
   established that current code already recognizes the exact response as a
   non-terminal quota casualty, then added end-to-end regression coverage and
   retry documentation in `5f11fd1`.
5. `codeprobe-8rdk`: investigated and closed as a misclassified no-op. The
   Requests admission loss came from an incomplete SCIP file universe, not
   missing codeprobe endpoint metadata.

The Requests seed-1 preflight initially admitted 8/14 tasks because its
project-generated Pyright/SCIP index covered only `src/`. The agents had read
the exact relevant files, including files under `tests/` and `docs/`, so the
index was rebuilt with those directories included. The original limited index
is preserved as `requests/index.pyproject-limited.scip` and
`requests/index.pyproject-limited.aoa.json`.

Three canonical Gunicorn trials ended in typed, non-quota infrastructure
timeouts: seed-2 baseline, seed-2 `aoa_migrated`, and seed-3
`aoa_migrated`. Their partial traces remained usable for paired-footprint
admission, so no candidates were silently discarded. Seed-3 baseline finished
naturally in about 404 seconds.

Several failed Rich seed-1 account-selection attempts are preserved separately
under names beginning `expB-quota-`; none is part of the canonical campaign.
Environment-based launcher selection was scrubbed by codeprobe's safe child
environment, so the launcher default—not an inherited environment
variable—was used for the successful canonical rerun.

Finally, the first K=3 packaging attempt omitted Rich seed-2 bridge replay and
therefore failed closed at 0/19 for Rich. Replaying all canonical trace
databases and rebuilding the same evidence made the real recorded `Read`
events visible and produced the final 70/70 gate above. This was an operator
sequencing error, not a codeprobe runtime defect.
