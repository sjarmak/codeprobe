# Asynchronous Intake and Consent

Participant budget: ten minutes maximum. Complete without repository names,
URLs, paths, code, prompts, patches, traces, task-level results, credentials,
logs, or diagnostics.

## Readiness

- [ ] I am the participant technical owner or have authority to operate the
  evaluation and approve any export.
- [ ] Python 3.11+ and an approved container or sandbox are available.
- [ ] The repository language and merge history are supported by the selected
  CodeProbe mining goal.
- [ ] Both selected agent configurations can run locally; credentials and cost
  limits are managed inside the participant environment.
- [ ] Network posture is predeclared as `offline`, `restricted`, or `approved`.
- [ ] I can select and attest at least ten paired distinct tasks and run three
  repeats per task and configuration.
- [ ] I will freeze the sampling plan and comparison dimension before viewing
  results.
- [ ] I can attend one structured session capped at 45 minutes; any security or
  platform follow-up is optional.

## Boundary consent

- [ ] No provider person will access the repository, source, or data-owner
  environment.
- [ ] I will not share repository identifiers, paths, source, prompts, patches,
  traces, task-level results, raw results, logs, diagnostics, or credentials.
- [ ] I will stop and record a disqualifying event if that boundary is crossed.
- [ ] I understand that only the exact five-artifact approved bundle may leave
  the environment.

## Export consent

Approval happens only after local preview. Supplying the final preview digest
confirms all four fixed statements:

- [ ] Privacy: no prohibited data is present.
- [ ] Sample fidelity: the sample and exclusions match the frozen plan.
- [ ] Result fidelity: the exported aggregates and findings match local
  results.
- [ ] Usefulness: the bounded conclusion is useful, including a decision not to
  advance either configuration.

Readiness status: `ready` / `blocked` / `declined`
